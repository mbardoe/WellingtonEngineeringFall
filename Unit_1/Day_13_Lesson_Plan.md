# Lesson Plan: Introduction to Version Control in OnShape (Spinner Project)

**Duration:** 70 minutes  

---

## Objectives
- Understand what **versions**, **branches**, and **merges** are in OnShape.  
- Learn how to create and manage versions in the history tree.  
- Practice branching from a base version, making changes, and merging back into Main.  

---

## Agenda (70 min)

### 1. Warm-Up Discussion (5 min)
- Ask: *“Why do engineers need to keep track of different versions of the same design?”*  
- Collect ideas: collaboration, testing ideas, avoiding mistakes, documentation.  
- Show the version history panel in OnShape.

---

### 2. Teacher Demo: Versions and Branches (15 min)
- Open a simple OnShape part (e.g., a cube with a hole).  
- Demonstrate:  
  1. Create a **Version** called `Base Part`.  
  2. Create a **Branch** from that version.  
  3. Make a change in the branch (resize the hole).  
  4. Show the history tree and explain how branches are separate from Main.  
- Emphasize: Main = “official design,” branches = “experiments.”

---

### 3. Guided Practice: Create Base Version (10 min)
- Students open the provided **Spinner file**.  
- In the history tree, create a version called `Base Spinner`.  
- Check that all students have the version saved before continuing.  

---

### 4. Guided Practice: Branching (10 min)
- From `Base Spinner`, students create **two separate branches**: `Branch A` and `Branch B`.  
- Confirm that both branches appear in the tree.  

---

### 5. Independent Work: Modify Branches (15 min)
- In **Branch A**, make one noticeable change (e.g., change hole size, arm length, or add cutouts).  
- In **Branch B**, make a different change (e.g., add text, fillets, or change thickness).  
- Encourage experimentation, but remind them each branch must be clearly different.  

---

### 6. Teacher Demo: Merging (5 min)
- Demonstrate how to merge one branch back into **Main**.  
- Show how the history tree now records the merge.  

---

### 7. Student Practice: Merge (5 min)
- Students choose their preferred branch (A or B) and merge it back into Main.  
- Teacher circulates to check history trees.  

---

### 8. Reflection (5 min)
- Quick write: *“What did you change in Branch A? What did you change in Branch B? Which branch did you merge, and why?”*  
- Volunteers share answers.  

---

## Homework
- Finish both branches with at least one clear design change.  
- Merge one branch back into Main.  
- Write a short reflection (5–6 sentences):  
  - What you changed in each branch  
  - Which branch you merged, and why  
  - Why version control is useful in engineering  

---

## Materials
- Projector with OnShape open (for demo).  
- Provided **Spinner file** in OnShape.  
- Student laptops with OnShape access.
